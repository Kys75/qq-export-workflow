# macOS 权限准备与恢复保护（可选高级步骤）

本页用于首次在自己的 Mac 上配置 QQ NT 导出、且已经遇到具体权限错误时排查。普通导出与读取已解密快照不需要关闭 SIP。已知数据库密钥时，优先使用 README 的 `set-key`；进程扫描只是在没有当前密钥时的一条可选路径。

本页只提供人工操作说明。安装程序和 Agent 不会自动提权、进入恢复模式、修改 SIP、降级 QQ、重签 QQ 或修改启动安全策略。是否调整保护由设备所有者决定；受单位管理的设备应遵循管理员设置。

## 先区分是哪一层权限

| 现象或设置 | 它影响什么 | 不代表什么 |
| --- | --- | --- |
| 源库路径错误、文件不存在 | 当前账号的数据库定位 | 不应据此修改系统保护 |
| `Operation not permitted` / 文件读取被拒 | macOS 隐私权限、目录访问或文件权限 | 不一定是 SIP 导致 |
| 完全磁盘访问权限（Full Disk Access） | 允许获授权的应用读取受隐私保护的数据位置 | 不授予 QQ 进程调试权限 |
| `sudo` | 以 root 身份执行这一次命令 | 不绕过所有隐私或进程保护，也不等于 SIP 已关闭 |
| `macOS denied process access` | `task_for_pid` 无法取得 QQ 进程访问权 | 不证明一定可以通过关闭 SIP 解决 |
| 扫描结束但没有经过验证的密钥 | 当前进程中的候选格式、数据库参数或版本可能不匹配 | 不应继续扩大系统权限作为默认补救 |

先在仓库目录执行 `doctor` 检查文件定位与依赖，再对实际失败的步骤处理权限。不要把密钥或数据库发到聊天窗口作为排查材料。

## 1. 必要时授予完全磁盘访问权限

如果源库确实存在，但通过终端运行时读取被 macOS 拒绝：

1. 打开「系统设置 → 隐私与安全性 → 完全磁盘访问权限」。旧版 macOS 位于「系统偏好设置 → 安全性与隐私 → 隐私」。
2. 为你实际用于执行命令的终端应用授权，例如 Terminal 或 iTerm。若从其他桌面应用内运行命令，权限归属可能不同；最简单的诊断方式是在已授权的终端中手工执行 README 命令。
3. 按系统提示退出并重新打开该应用，再次尝试读取。不要给所有应用批量授权。
4. 导出完成后，如果不再需要持续访问，可在同一页面撤回此次授权。

完全磁盘访问权限不会自动解决进程内存访问限制，也不需要与 SIP 修改绑定操作。MCP 日常读取仓库外的解密副本与首次访问 QQ 数据容器是不同步骤。

## 2. 检查当前 SIP 状态，再决定是否继续

在正常 macOS 终端只读检查：

```bash
csrutil status
```

记录当前状态。`enabled` 表示开启；`disabled` 表示关闭；若显示自定义或部分关闭状态，先查明设备原有配置，不直接用本页命令覆盖管理员策略。不要把“当前已关闭”当作应该永久关闭的理由。

在已正确配置的仓库内，先按 README 尝试普通 `scan-key --allow-process-memory`。如果只缺执行身份、且你已决定进行进程扫描，可人工使用 README 中带绝对 Python 路径和明确配置路径的 `sudo` 命令。若仍然提示进程访问被拒，请选择以下路径之一：已有合法密钥、已经获准调试的环境，或在理解影响后自行执行下一节。

**临时关闭 SIP 会降低系统级保护，且不能保证当前 macOS 与 QQ 版本允许扫描成功。** SIP 之外还可能有应用签名、运行时保护和组织策略限制。本文不要求进一步降低启动安全策略、关闭 authenticated root、降级或重签 QQ。

## 3. 如自行决定临时调整 SIP，使用 macOS Recovery

先保存工作，确认能够进入恢复模式并掌握管理员凭据。提前读完第 4 节的恢复步骤；不要在尚未掌握恢复方法时开始。以下操作应由设备所有者在本机完成。

### Apple Silicon（M 系列）

1. 从苹果菜单选择关机，等待 Mac 完全关闭。
2. 按住电源按钮，直到出现启动磁盘和「选项」。
3. 选择「选项 → 继续」。如系统询问，选择恢复的磁盘及管理员账户，并输入凭据。
4. 进入恢复环境后，从菜单栏「实用工具 → 终端」打开终端。

### Intel Mac

1. 重启 Mac，并立即按住 `Command-R`，直到出现 Apple 标志或恢复启动画面。
2. 如系统询问，选择管理员账户并完成身份验证。
3. 进入恢复环境后，从菜单栏「实用工具 → 终端」打开终端。

### 在恢复环境内临时关闭，然后重启

仅在你已明确决定进行此次临时调整时，在恢复环境终端输入：

```bash
csrutil disable
```

按当前系统提示确认并进行身份验证。如果命令被设备策略拒绝，停止，不继续绕过策略。执行成功后从苹果菜单重启进入正常 macOS；状态变更需要重启生效。

正常启动后执行 `csrutil status`，核实实际状态。打开 QQ、登录目标账号并打开聊天，让数据库加载。在仓库目录手工执行：

```bash
sudo "$PWD/.venv/bin/python" -m qq_export_workflow --config "$HOME/.config/qq-export-workflow/config.toml" scan-key --allow-process-memory
```

这条命令假设你已按 README 创建 `.venv` 和配置。如果使用自定义配置，应替换该配置参数。`sudo` 下配置中的 `~` 仍按发起用户展开。工具会验证密钥并保存到私有文件，不打印密钥；不要使用 `cat` 把密钥展示给 Agent。

**扫描成功、失败或放弃后，都立即进入下一节恢复 SIP。** 若扫描失败，不在保护降低的状态下继续尝试不相关的系统改动。若成功，先正常退出 QQ，避免数据库继续变化；不要手工删 WAL，也不要让 QQ 在恢复后首次登录时自动重新打开。

## 4. 立即恢复 SIP 并核实

1. 按第 3 节对应芯片的步骤再次进入 macOS Recovery。
2. 打开「实用工具 → 终端」。
3. 执行恢复命令，并按系统提示确认：

   ```bash
   csrutil enable
   ```

4. 命令成功后重启回正常 macOS。
5. 再次执行 `csrutil status`，确认结果为 `enabled`。恢复命令成功但尚未重启，不能当作已验证恢复完成。如果恢复被拒绝，留在恢复环境按系统提示处理，必要时联系设备管理员或 Apple 支持；不要把关闭状态当作完成。

SIP 恢复并核实后，保持 QQ 关闭，用普通用户运行：

```bash
.venv/bin/qq-export refresh
.venv/bin/qq-export list
```

SIP 恢复不妨碍使用已经合法取得的密钥解密本地文件。但 QQ 重新启动、重新登录或版本变化可能更换密钥，因此不要把“曾扫描成功”理解为今后永久有效。如果刷新失败，核对源库、WAL、参数和密钥适用状态；失败不会发布新快照，不要为此自动再次关闭保护。

后续日常使用保持 SIP 开启，用普通用户执行 CLI/MCP。需要新密钥时，重新评估是否有已有密钥或获准调试环境，而不是把安全设置修改加入自动刷新流程。
